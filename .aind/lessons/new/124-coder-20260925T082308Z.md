## Observation
A hand-generated Fluent BrandVariants ramp (16 shades from one brand color, needed because Fluent's own ramp-generator tool has no scriptable API) is easy to get subtly wrong in a way that isn't visible just by eyeballing the hex values: the first version anchored shade 80 to the input color's exact HSL lightness instead of a clean monotonic step, which both broke the dark-to-light ordering (shade 80 ended up lighter than shade 90) and dropped shade 80's contrast against white text below the WCAG AA minimum (about 3.6:1, where Fluent's own stock ramp is comfortably above 4.5:1 at that shade). Code review caught it by reasoning about the shade values, not by rendering anything. Generating a custom ramp should include a monotonic-lightness check and a contrast check (e.g. against white, at the shade Fluent uses for default button backgrounds) as part of building it, not as an afterthought.

## Observation
A one-time effect that reacts to async data becoming ready (e.g. auto-applying a default saved view once mail + a second data source have both loaded) needs its setState call deferred into a callback (e.g. queueMicrotask, mirroring the existing .then()-callback pattern in useCategorizedMail's load effect) to satisfy react-hooks/set-state-in-effect — calling setState synchronously in the effect body trips the rule even when the call is correctly guarded by a ref so it only ever fires once. This is not obvious from the rule's name and cost an extra lint-fix cycle; worth a short example in frontend-architecture.md's existing note on this rule.

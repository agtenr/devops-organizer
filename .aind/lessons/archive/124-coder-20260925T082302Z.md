## Observation
Overriding one of Fluent UI v9's own built-in interaction states (hover/pressed color on a Button) needs the exact pseudo-selector Fluent's own compiled styles use, not a plausible-looking one. Fluent's pressed state is authored as two separate selectors, ':hover:active' (mouse) and ':active:focus-visible' (keyboard), which its build step then merges into one compiled rule only when both have an identical declaration value. A single, hand-written ':hover:active' key looked complete (it compiled fine and covered the mouse case) but silently missed the keyboard-press case — this took two review passes to catch and fix, and needed grepping the library's compiled CSS to find the real selector. Anyone recoloring a Fluent component's interaction states should check the library's compiled output for the exact selectors first, not guess from CSS conventions.
